## OVERVIEW

Astro 6 + Starlight static documentation site for Iris shader pack authors.
The product is the MDX corpus: 121 pages feed one Starlight collection, static pages, and per-page OG images.

## CONVENTIONS

- Use pnpm. `pnpm-lock.yaml` matches `package.json` and CI; `package-lock.json` is stale.
- Keep ESM and Astro strict TypeScript. No repository formatter exists; preserve nearby style.
- Treat framework wiring as entry points: config registration, file placement, and exported route handlers matter more than import counts.
- `src/assets/` is processed by Astro; `public/` passes files through unchanged at fixed root URLs.
- Theme backgrounds are eagerly globbed from both `src/assets/banners/dark/` and `light/`; add corresponding variants to both sets.
- Commit and PR titles use `(type): (area): description`; allowed types are `feat`, `fix`, `chore`, `mod`, `refactor`, `revert`.

## ANTI-PATTERNS (THIS PROJECT)

- Do not edit or commit `dist/`, `.astro/`, or `node_modules/`; they are generated.
- Do not assume `src/pages/` owns normal docs routes; Starlight discovers them from `src/content/docs/`.
- Do not report security vulnerabilities through public GitHub issues; follow `SECURITY.md`.

## UNIQUE STYLES

- Filesystem content categories intentionally use title case and spaces (`Guides`, `How To`, `Shaders.Properties`); preserve those names.
- `Head.astro` and `BannerImage.astro` independently choose random theme images; `root.css` renders their background hooks.
- Each content entry ID maps to `/og/<entry-id>.png`; title and description drive the generated social card.
